## §0. Exam environment drill — the per-host line

**Rewritten 26 Sep from the LF page** (`plan.md §13`). Every exam SSH host ships
`kubectl` with the **`k` alias and Bash completion already configured**; `base`
has neither; nothing you export survives an `exit`. So the 4-line boot block of
14 Sep **retires**: two of its lines are free in the exam, and the other two must
be re-run on every host anyway.

**Runs on: every host where you will generate or edit YAML.** Target **10 s**, one
line, from memory:

```bash
export do="--dry-run=client -o yaml"; printf 'set ts=2 sw=2 et ai\n' > ~/.vimrc
```

🔍 `k run t --image=nginx $do | head -3` → prints `apiVersion: v1`.

Skip it on purely imperative tasks (scale, label, set image, drain, upgrade,
etcd). `$do` is always used **unquoted**: `k run x --image=nginx $do > x.yaml`.

🧪 **The lab mirrors the exam.** Alias and completion go **permanently** into
`~/.bashrc` on cp1, w1 and w2 — they are free in the exam, so typing them is
wasted practice. Once, on each node:

```bash
# ▶▶ cp1, w1, w2 🧪 — once; then re-snapshot
cat >> ~/.bashrc <<'EOF'
source <(kubectl completion bash)
alias k=kubectl
complete -o default -F __start_kubectl k
EOF
```

`$do` and `.vimrc` stay **out** of `.bashrc` on purpose: they are the drill.

**`k config use-context <ctx>` is not part of the line.** It is step zero of every
task, not configuration.

**What `set ts=2 sw=2 et ai` means:**

| Option | Name | Effect |
|---|---|---|
| `ts=2` | tabstop | a Tab character *displays* as 2 columns |
| `sw=2` | shiftwidth | `>>`, `<<` and autoindent move 2 spaces |
| **`et`** | **expandtab** | 🔴 Tab inserts **spaces**, never a Tab character |
| `ai` | autoindent | Enter inherits the previous line's indentation |

**`et` is the one that costs tasks.** YAML forbids Tab characters for
indentation. Without `et` the file looks perfect and `kubectl apply` fails with
`error converting YAML to JSON: found character that cannot start any token`.

**Rules that cost tasks, not seconds:**

| Rule | Why |
|---|---|
| `k config use-context <ctx>` first, every task | The exam spans several clusters. Right answer, wrong cluster = zero |
| Read the task twice; say the verification command out loud **before** starting | `READ` fired 5× in one day during KCNA |
| 8 minutes with no answer → flag, move on, come back | Partial credit beats a perfect task never opened |
| Never reboot the node named `base` | It does not restart your environment |
| INSERT key is prohibited | Enter insert mode in vim with `i` |
| `Ctrl+Alt+W`, never `Ctrl+W` | `Ctrl+W` closes your only docs tab |

Docs: only `kubernetes.io/docs`. Do not browse the tree — use the search box with
the exact object name, or `kubectl explain --recursive <kind>.spec`. Each bullet
gives you its search term.

## §0.1 Execution location — the most expensive mistake is the right command on the wrong machine

| Layer | Prompt | Role | Runs here |
|---|---|---|---|
| **Host** | `cposada@cposada:~$` | Hypervisor console. **Not part of Kubernetes** | `multipass` only |
| **cp1** | `ubuntu@cp1:~$` | **The exam surface** | `kubectl`, `kubeadm`, `etcdctl`, `crictl`, `ssh w1` |
| **w1 / w2** | `ubuntu@w1:~$` | Nodes, reached **from cp1 by SSH** | `kubeadm upgrade node`, `apt`, `systemctl`, `crictl` |

> **The host runs `multipass` and nothing else.** Enter with `multipass shell cp1`
> and stay there until the session ends. Every command block in these files
> carries a banner; **a block with no banner is a defect — report it, do not run it.**

```
# ▶▶ HOST — cposada@cposada
# ▶▶ cp1  — ubuntu@cp1
# ▶▶ w1   — ubuntu@w1   (enter with: ssh w1, from cp1)
```

Guard before any `sudo` from a runbook: **`hostname`**.

**Commands that damage the host if mistyped there:**

| Command | Damage |
|---|---|
| `sudo swapoff -a` + `sed -i '/ swap /' /etc/fstab` | Disables desktop swap, **persistently** |
| `apt-get install kubelet kubeadm` | A kubelet crash-looping on your desktop forever |
| `sudo systemctl restart containerd` | Only if containerd/Docker is installed there |

### Host audit — completed 12 Sep, host is clean

| Check | Result |
|---|---|
| `/etc/apt/sources.list.d/*kube*` | **absent** — the repo `sed` cannot damage this host |
| `dpkg -l \| grep kubelet\|kubeadm` | **empty** |
| swap | **intact**, `/etc/fstab` uncommented |
| `prep-node.sh` | always run via `multipass transfer` + `multipass exec`, never locally |
| `kubectl` | two: `/usr/local/bin` v1.36.1 (wins PATH) and snap v1.36.3 |
| `~/.kube/config` | one context, the lab, no EKS — a **static copy** of `admin.conf` from 31 Aug |

⚠️ **Both host clients are two minors ahead of the cluster**, outside the
supported ±1 skew. Neither is used. The `kubectl` that matters is the apt package
on cp1, because it moves with the cluster through `kubeadm upgrade`.

🔴 **Violated once, 13 Sep** (`kubectl get node` from the host). It worked, which
is exactly the problem — the habit does not self-correct. Row in `mistakes.md`.

⚠️ **EKS:** there is no equivalent table in your day job, because there is no
machine you are allowed to stand on. *Which host you are on changes what a
command means* is itself a vanilla-Kubernetes idea, and half of D5.

## §0.3 🧪 Snapshot and restore — multipass mechanics

**Runs on: HOST.** Multipass requires the instance **STOPPED** for both.

```bash
# ▶▶ HOST — RESTORE (all three, always together)
# use lab-v136 for upgrade runs; lab-v137 for everything else
multipass stop cp1 w1 w2
for n in cp1 w1 w2; do multipass restore $n.lab-v137 --destructive; done
multipass start cp1 w1 w2

# ▶▶ HOST — SNAPSHOT
multipass stop cp1 w1 w2
for n in cp1 w1 w2; do multipass snapshot $n --name <name>; done
multipass start cp1 w1 w2
multipass list --snapshots
```

> **Fixed 17 Sep:** the comment used to sit before `; done`, which commented the
> `done` out and left the shell hanging on `>`.

### 🧪 Card — snapshot / restore

```
ALWAYS    all three VMs, stopped, together — snapshot, restore AND delete (running VM = disk lock)
RESTORE   stop → for n in cp1 w1 w2; do multipass restore $n.<snap> --destructive; done → start
SNAPSHOT  clean ~/.vimrc + history → stop → for n …; do multipass snapshot $n --name <name>; done → start
WAIT      ~4:30 total · discard the first `kubectl get nodes`
SKEW      x509 "expired or not yet valid" → compare `date` with the host → restart systemd-timesyncd
```

### Snapshot inventory — canonical copy in `plan.md §8`

| Snapshot | Version | `k` alias | Tools | Use |
|---|---|---|---|---|
| **`lab-v137`** | 1.37.1 | ✅ 3 nodes | crictl + yq 3 nodes · etcd 3.7.0 + helm on cp1 | **default** — everything except upgrade |
| **`lab-v136`** | 1.36.5 | ✅ 3 nodes | crictl + yq 3 nodes · etcd 3.6.8 + helm on cp1 | upgrade runs (→ 1.37.x) · Set 1 |
| `w3.cleanw3` | bare Ubuntu | — | — | 1.2 runs · the base for every w3 sim (`cka-D1-1-install.md §W3`) |

A snapshot freezes everything installed **before** it; restoring an older one
removes tools from `/usr/local/bin`. Before any snapshot: `rm -f ~/.vimrc` and
`history -c && rm -f ~/.bash_history`.

🔴 **Why `base-v134` exists.** Restoring `clean-v134` on 14 Sep wiped the shell
block and the SSH keys — they were added 12 Sep, after that snapshot was taken.
Result: `k: command not found` and `Permission denied (publickey)` mid-run, plus
~5 minutes of re-setup polluting the clock. **Take `base-v134` before a run,
never after**, or the baseline is a post-upgrade state and the drill has nothing
left to do.

**Traps, all hit for real:**

1. **Restoring only cp1** leaves the workers newer than etcd. Three or none.
2. **Dots are invalid in snapshot names** — `clean-1.34` was rejected 31 Aug.
3. After `sudo snap restart multipass`, `multipass list` fails with a socket error for ~10 s. Timing, not a fault.
4. **`busybox:1.36` returns NXDOMAIN on short names.** Pin **`busybox:1.28`** for DNS tests.
5. **Never `-w`** in a timed drill — it hangs the terminal.
6. Instance IPs are **deterministic** across stop/start, daemon restart and host power cycle. Hard-coding them in `~/.ssh/config` is safe.
7. **`apt upgrade` is forbidden on a node.** Packages are held; only explicit `apt-get install <pkg>=<version>`.

**Cost, measured:** the stop→restore→start cycle is **3 min**, plus **~90 s** of
convergence. The cluster is not usable when `multipass list` says `Running`, and
`kubectl get nodes` answers `Ready` before it, off stale etcd state. **Budget
~4:30 and discard the first `get nodes`.**

⚠️ **Clock skew.** A VM resumed from a snapshot carries a stale clock. Symptom:
`x509: certificate has expired or is not yet valid`. **Not a certificate
problem.** Diagnose by comparing `date` against the host — **not** with
`kubeadm certs check-expiration`, which needs a trustworthy clock to mean
anything. Fix: `sudo systemctl restart systemd-timesyncd`.

## §0.4 🧪 One-time lab setup — baked into `lab-v135` and `lab-v134` (26 Sep)

```bash
# ▶▶ cp1
cat >> ~/.bashrc <<'EOF'
source <(kubectl completion bash)
alias k=kubectl
complete -o default -F __start_kubectl k
export do="--dry-run=client -o yaml"
EOF
printf 'set ts=2 sw=2 et ai nu\nsyntax on\n' > ~/.vimrc
echo "export PS1='\[\e[1;31m\]\h\[\e[0m\]:\w\$ '" >> ~/.bashrc
source ~/.bashrc

ssh-keygen -t ed25519 -N '' -f ~/.ssh/id_ed25519
cat ~/.ssh/id_ed25519.pub
```

```bash
# ▶▶ HOST — push the key to both workers, once
for n in w1 w2; do
  multipass exec $n -- bash -c "mkdir -p ~/.ssh && echo '<PUBKEY>' >> ~/.ssh/authorized_keys && chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys"
done
```

```bash
# ▶▶ cp1
cat >> ~/.ssh/config <<'EOF'
Host w1
  HostName 10.167.152.24
  User ubuntu
  StrictHostKeyChecking no
Host w2
  HostName 10.167.152.155
  User ubuntu
  StrictHostKeyChecking no
EOF
chmod 600 ~/.ssh/config
ssh w1 hostname && ssh w2 hostname
```

**Verify:** prompt shows the hostname in red · `type __start_kubectl` responds ·
`echo $do` prints the string · `ssh w1 hostname` → `w1`, no password.

> The `PS1` colour is scaffolding. The **SSH config is not** — in the exam you
> work from one node and `ssh node01` into the others. Trust is one-way: cp1 →
> workers. `ssh cp1` from a worker failing with `Permission denied (publickey)` is
> correct, and matches the exam, where you come back with `exit`.
>
> 🧪 `StrictHostKeyChecking no` disables verification of the server's host key —
> it silently accepts a new fingerprint instead of warning you. Fine in a lab you
> own; an audit finding anywhere else, because it removes the only defence
> against a man-in-the-middle on SSH. CKS material; the decision is here.
